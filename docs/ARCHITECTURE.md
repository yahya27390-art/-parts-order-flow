# البنية والقرارات التقنية

## نظرة عامة

```
المتصفح (React 18 + Vite 6)
   │
   ├── React Query  → كاش/إبطال/حالة تحميل موحّدة
   │
   ├── features/*   → منطق العمل النقي (logic.js) + طبقة البيانات (api.js) + hooks.js
   │
   └── api/supabaseClient.js → عميل Supabase (PostgREST + Auth + Storage)
                                   │
                                   ▼
                        PostgreSQL (Supabase)
                        ├── جداول المستندات (طلبات/أذونات/أصناف)
                        ├── stock_movements (دفتر الحركات)
                        ├── دوال RPC ذرية
                        └── RLS + profiles (الأدوار)
```

## طبقات التطبيق

| الطبقة | الملفات | المسؤولية |
|---|---|---|
| طبقة الاتصال | `src/api/supabaseClient.js`, `errors.js`, `databaseClient.js` | إنشاء العميل، قراءة مُصفّحة (`selectRows`)، عدّادات (`countRows`)، استدعاء RPC، التخزين، وقراءة المستخدم ودوره |
| منطق العمل النقي | `src/features/*/logic.js` | حسابات قابلة للاختبار بلا React ولا شبكة (تُختبر بـ `node --test`) |
| طبقة البيانات | `src/features/*/api.js` | تنفيذ العمليات: يفضّل RPC الذرّي، ويرجع لمسار بديل مكافئ عند غياب الترحيلات |
| حالة الواجهة | `src/features/*/hooks.js` | React Query: مفاتيح الكاش، الإبطال بعد كل تعديل، رسائل الخطأ العربية |
| الواجهة | `src/pages`, `src/components` | العرض فقط؛ لا استعلامات مباشرة ولا منطق حسابات |

## قرارات تقنية مُتعمَّدة

1. **المنطق النقي منفصل عن الواجهة.** كل قاعدة حسابية موجودة في `logic.js` ومغطّاة باختبارات، فلا يمكن
   أن تنحرف قواعد المخزون بين صفحة وأخرى.
2. **لا كتابة مباشرة على جداول المستندات من الواجهة.** كل عملية مؤثّرة على الأرصدة تمرّ عبر دالة قاعدة بيانات
   (`create_purchase_order`, `receive_goods`, ...) تنفّذها داخل **معاملة واحدة**.
3. **دفتر الحركات هو المصدر الرسمي للأرصدة.** `items.current_stock` مُشتق ويُحدَّث بمُشغِّل (trigger) من الحركات،
   ما يتيح تدقيقًا كاملًا وإمكانية عكس أي عملية.
4. **الإلغاء بدل الحذف.** أي مستند له أثر مخزني يُلغى (`voided_at`) وتُسجَّل حركات عكسية بدل حذفه.
5. **مساحة عمل واحدة متعددة الأدوار.** الأدوار في جدول `profiles`، وتُفرض على مستوى القاعدة (RLS + trigger)
   لا في الواجهة فقط.
6. **تحميل كسول للصفحات** (`React.lazy` في `pages.config.js`) لتقليل الحزمة الأولى.
7. **تصدير CSV آمن** (`lib/csv.js`) مع تهريب الفواصل وعلامات التنصيص و BOM لـ Excel العربي.
8. **RTL أصلي**: `index.html` بـ `dir="rtl"` و`lang="ar"`، والخط Tajawal.

## مسار بديل تلقائي (Graceful degradation)

الواجهة تفحص مرة واحدة (`stock_api_version()`) هل الترحيلات المطوّرة مطبَّقة:

- **مطبَّقة** → كل العمليات عبر RPC ذرّي (الوضع الموصى به).
- **غير مطبَّقة** → مسار بديل في `api.js` بنفس القواعد لكن بلا ذرّية كاملة، حتى لا يتعطّل العمل.

الشرط: إبقاء `api.js` (المسار البديل) و`logic.js` متوافقين مع دوال SQL. أي تغيير في قاعدة عمل يجب أن يُطبَّق
في الثلاثة: SQL + logic.js + اختبارات.

## الأداء

- بحث/فلترة/ترقيم **على الخادم** (`selectRows` مع `range`, `ilike`, `count: exact`).
- عدّادات لوحة التحكم عبر `head: true` (بلا نقل صفوف).
- عروض تجميع على الخادم: `v_inventory`, `v_order_fulfillment`, `v_supplier_discrepancies`.
- بحث مؤجّل (350ms) في `useListParams` بدل إطلاق طلب لكل ضغطة مفتاح.
