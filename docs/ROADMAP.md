# خطة التطوير

## ✅ منجز في هذه الدفعة

### سلامة البيانات
- دفتر حركات مخزون `stock_movements` كمصدر رسمي للأرصدة + متوسط تكلفة من الحركات.
- دوال RPC **ذرية** لكل العمليات (إنشاء/تعديل/إلغاء/حذف الطلبات، الاستلام، تعديل الإذن، إلغاء الإذن، تسوية الرصيد).
- ترقيم مستندات ذري `PO-YYYYMM-0001` بدل أرقام عشوائية.
- **تصحيح معنى الرصيد المتاح** (لا يتغيّر عند الطلب، ويزيد عند الاستلام فقط) + ترحيل الأرصدة القائمة.
- حالة الطلب تُحسب دائمًا من بنوده، وإعادة حسابها بعد أي تعديل/استلام/إلغاء.
- منع حذف بند مستلم، وإلغاء المستندات (void) مع عكس الأثر بدل الحذف.

### الأمان
- جدول `profiles` + أدوار (مدير/أمين مستودع/قارئ) + مُشغِّل إنشاء تلقائي عند التسجيل.
- استبدال سياسات RLS المفتوحة بسياسات أدوار، وفرض الدور بمُشغِّل يمنع تجاوز الدوال.
- قراءة الدور من `profiles` لا من بيانات قابلة للتعديل، وإيقاف الحسابات غير النشطة.
- تشديد تخزين الشعارات على مسار `logos/` + حد للحجم والنوع + حذف الشعار القديم.

### الأداء
- React Query لكل قراءة (كاش + إبطال + حالة تحميل موحّدة بدل `useEffect` في كل صفحة).
- بحث/فلترة/ترقيم على الخادم + عدّادات `head: true` + عروض تجميع (`v_inventory`, `v_order_fulfillment`, ...).
- تحميل كسول للصفحات + بحث مؤجّل + تقليل نقل البيانات في لوحة التحكم والتقارير.

### الجودة والتنظيم
- فصل المنطق النقي (`logic.js`) عن الطبقة (`api.js`) عن الحالة (`hooks.js`).
- **36 اختبارًا** لمنطق الأعمال بـ Node test runner (بلا اعتماديات إضافية) + `npm run check`.
- معالجة أخطاء موحّدة برسائل عربية، و`schemas.js` (zod) للتحقق.
- مكوّنات مشتركة: `PageHeader`, `StatCard`, `StatusBadge`, `EmptyState`, `TablePagination`,
  `ConfirmDialog`, `PrintStyles`, `ItemCombobox` — وحذف تكرار كان منتشرًا في ٤ صفحات.
- تصدير CSV آمن (كان يُنتج ملفات مكسورة) + توكنات تصميم في Tailwind + `lang/rtl` صحيح + توثيق كامل.

## 🔜 المرحلة القادمة (مقترحة بالترتيب)

### 1) إدارة الموردين ككيان
جدول `suppliers` بدل `supplier_name` النصي، مع كود/هاتف/بيانات ضريبية، وتقارير أداء لكل مورد
(نسبة الزيادات/النواقص/التأخير). يمهّد للمطابقة الثلاثية.

### 2) المطابقة الثلاثية والفاتورة
`supplier_invoices` + مطابقة (طلب ↔ استلام ↔ فاتورة) وكشف فروقات مالية لكل فاتورة،
ويُبنى على `v_supplier_discrepancies` الموجود.

### 3) التكاليف الإضافية (Landing cost)
شحن/جمارك/تخليص موزّعة على بنود الإذن بحسب القيمة أو الوزن أو الكمية، لتصحيح `average_cost`
لأصناف مستوردة من كوريا.

### 4) تعدد المستودعات
`warehouses` + `stock_by_location` + تحويلات بين المواقع، مع إمكانية توزيع الأرصدة في تقرير المخزون.

### 5) الجرد الدوري
جلسات جرد (`stock_takes`) ببنود وتوليد فروق تُسدَّد عبر `adjust_item_stock` مع سبب مرجعي للجلسة.

### 6) حد إعادة الطلب والطلبات المقترحة
`reorder_point` و`max_level` في `items` + تقرير "اقتراح طلب شراء" بناءً على الاستهلاك والرصيد.

### 7) المرتجعات للمورد
`return_to_supplier` (الحركة موجودة في الدفتر) + إشعار دائن وربطه بالمطالبة المالية.

### 8) العملات وسعر الصرف
تعدد العملات (KRW/USD/SAR) مع سعر صرف في تاريخ المستند، بدل ر.س فقط.

### 9) تجربة المستودع
- مسح بالكاميرا (QR/Barcode) عبر `html5-qrcode` مع وضع تسجيل متواصل.
- طباعة ملصقات باركود للأصناف وأرفف.
- PWA + عمل بلا اتصال (Service Worker + طابور مزامنة) لشبكة المستودع الضعيفة.

### 10) التدقيق والإشعارات
- Audit log لكل تعديل (من/متى/قبل/بعد) + عرضه في صفحة تفاصيل المستند.
- إشعارات للطلبات المتأخرة (منطق ٢٠ يومًا موجود في لوحة التحكم) ورصيد منخفض.

### 11) تحويل باقي الصفحات إلى نفس النمط
`PurchaseOrderDetails` و`GoodsReceiptDetails` و`EditPurchaseOrder`/`EditGoodsReceipt` أصبحت عملياتها
عبر الطبقة الجديدة، لكن قراءتها لا تزال مباشرة؛ الخطوة القادمة تحويلها إلى `useOrderDetail`/`useReceiptDetail`
مع `PrintStyles` المشترك، ثم نقل صفحات الـ `Edit` إلى RHF + zod بالكامل.

### 12) TypeScript تدريجيًا
البدء بـ `api/`, `lib/`, `features/*/logic.js` (الأسهل والأعلى قيمة) ثم الطبقات الأعلى.
